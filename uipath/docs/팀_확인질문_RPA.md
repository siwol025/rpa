# ④ RPA → 팀 확인 질문 (2026-11-24)

## 현재 ④ 진행 상황 (공유용)
- 파일 감지 → Orchestrator 큐 → 검증 → 엑셀 기입 → 피벗·대시보드 갱신까지 동작합니다 (5분마다 자동 실행).
- 입력은 예린님 `call_schema.json` v1.0 JSON을 `Runtime\out` 폴더에서 읽습니다.
- 막혀 있는 부분: 서버 API 연동, ③ 분석 호출, 웹 화면과의 KPI·상태 표기 통일.

## ③ 예린
1. **분석 호출 방식**: 제가 ③ 워크플로우를 호출하나요, 아니면 예린님이 JSON을 폴더에 넣어 주면 제가 읽나요? (지금은 후자로 구현)
2. `agent_name`이 null이면 파일명에서 뽑아 채우나요?
3. `call_datetime`이 null이면 `source.received_at`으로 대체해도 되나요?
4. 분류는 `type` 하나로 확정인가요? 업무/주제/통화시간 필드가 추가될 예정인가요?

## ① 백엔드
1. 상태 보고 키는 `call_id` 문자열인가요, 서버가 부여하는 id인가요?
2. R-06(전사 적재)과 R-07(분석 적재)은 로봇(④)이 호출하나요, ③이 호출하나요?
3. 로봇 PC IP를 `ROBOT_ALLOWED_IPS`에 등록해야 합니다. 필요한 값과 `X-API-Key` 전달 방법을 알려 주세요.
4. 409 응답이 오면 로봇은 어떻게 처리할까요? (무시 / 로그만 / 재시도)
5. 서버가 openpyxl로 엑셀 양식을 채우면 슬라이서·차트가 사라집니다. 로봇이 만든 보고서 파일을 그대로 내려받게 할 수 있을까요? (W-11)

## ② 프론트
1. 상태 표기를 `SUCCESS / NEEDS_REVIEW / FAILED`로 맞출까요, "완료 / 분석 중 / 실패"로 맞출까요? (엑셀은 정상 / 확인필요 / 예외 시트)
2. 대시보드 KPI(상담 건수, 불만 비율, 자동 처리 완료율, 평균 통화시간) 정의를 알려 주세요. 평균 통화시간은 JSON의 `source.duration_sec`를 쓰면 되나요?

## 전체 팀
- 역할 정의에 있는 **CRM/ERP 입력 자동화**가 이번 범위에 포함되나요? 포함이면 대상 시스템(모의 화면 포함)을 알려 주세요.
