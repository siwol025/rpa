# 정기 보고서 업로드·제공 규격안 (제안, 팀 합의 전)

| 항목 | 내용 |
|---|---|
| 대상 기능 | `features.md` W-11 중 **정기 보고서**: 로봇이 만든 보고서 파일(피벗·슬라이서 포함)을 서버에 올리고, 웹에서 목록을 보고 내려받는다. 기간 지정 보고서(`GET /api/reports/excel`)와 별개 |
| 배경 | RPA 파트 답변: 전달 방식은 업로드 API가 안정적(Drive 폴더 방식은 서버가 읽는 시점을 맞추기 어려움). 백엔드가 규격을 정하면 로봇에 업로드 단계를 추가 |
| 상태 | 아래 [결정 필요] 항목을 팀이 정한 뒤 구현 |

## 1. 흐름

1. 로봇이 정해진 주기에 보고서 파일을 만든다(지금처럼 `report\콜센터_보고서.xlsx`를 갱신하는 방식이면, 주기 마감 시점에 그 기간 파일을 따로 저장).
2. 로봇이 업로드 API로 파일과 기간을 보낸다.
3. 웹은 정기 보고서 목록을 보여 주고, 사용자가 골라서 내려받는다(서버는 파일을 바꾸지 않고 그대로 준다).

## 2. 로봇 API — 업로드

`PUT /api/robot/reports/{period_type}/{period_start}` (로봇 인증: `X-API-Key` + 허용 IP, 다른 로봇 API와 같음)

- 경로
  - `period_type`: `weekly` | `monthly` **[결정 필요: 주기 종류]**
  - `period_start`: 기간 시작일(KST, `YYYY-MM-DD`). 주간은 월요일, 월간은 1일이어야 한다(아니면 422)
  - 기간 끝은 서버가 계산한다(주간 = 시작 + 6일, 월간 = 그달 말일)
- 본문: `multipart/form-data`, 필드 `file` 1개
  - `.xlsx`만(확장자 + 파일 시작 바이트가 zip `PK`), 아니면 415
  - 크기 상한 `MAX_UPLOAD_MB`(기본 100MB) 초과 413. 지금 파일은 수십 KB
- 응답
  - 처음 올린 기간: `201 {"period_type", "period_start", "period_end", "size", "uploaded_at"}`
  - 같은 기간을 다시 올림: `200`, 같은 본문. **덮어쓴다**(로봇 재시도·재생성 대비, 멱등)
- 로봇 쪽 처리: 5xx·네트워크 오류는 재시도, 4xx는 재시도하지 않고 로그 남김(다른 로봇 API와 같은 규칙)

`PUT` + 경로에 기간을 넣은 이유: 같은 기간 재업로드가 자연스럽게 덮어쓰기가 되고, 로봇이 업로드 결과(새로 생성/덮어씀)를 상태 코드로 구분할 수 있다.

## 3. 웹 API — 목록·다운로드

- `GET /api/reports/periodic?period_type=weekly` → `200 {"items": [{"period_type", "period_start", "period_end", "size", "uploaded_at"}]}` (최신 기간 순, `period_type` 생략 시 전체)
- `GET /api/reports/periodic/{period_type}/{period_start}` → xlsx 파일 그대로(`Content-Disposition: attachment`, 파일명 `콜센터_보고서_{주간|월간}_YYYYMMDD-YYYYMMDD.xlsx`). 없으면 404

## 4. 저장

- 서버 파일 저장소에 `reports/{period_type}/{period_start}.xlsx`로 저장(음성 사본과 같은 볼륨, 별도 폴더). 업로드 시각·크기는 파일 속성에서 읽는다
- **DB 테이블을 만들지 않는다**: 목록은 폴더를 읽어 만든다. 보고서 수가 적고(1년 주간 52 + 월간 12), 마이그레이션 없이 끝난다
- 임시 파일에 다 쓴 뒤 이름을 바꿔(원자적 교체) 다운로드 중인 파일이 반쯤 바뀌지 않게 한다
- 백업: `deploy/backup.sh`의 음성 볼륨 백업에 함께 포함된다

## 5. 보관 **[결정 필요]**

- 제안: 주간 52개(1년), 월간 24개(2년)를 넘으면 오래된 것부터 업로드 시점에 지운다
- 보고서에는 담당자·고객사 이름이 들어 있다. 음성·전사 보존 기간(E-07)이 정해지면 그보다 길게 두지 않는다

## 6. 결정 필요 (팀)

1. 주기: 주간·월간 둘 다인지, 하나만인지 (일간이 필요하면 `daily` 추가)
2. 주간 기준: 월~일(제안) / 다른 기준
3. 로봇이 업로드하는 시점: 기간이 끝난 다음 날 새벽(제안). 기간 중간에 미리 올리고 마감 후 덮어쓰는 것도 가능
4. 보관 개수(§5)
5. 웹 화면: 대시보드에 "정기 보고서" 목록을 둘지, 별도 메뉴로 둘지(프론트)
